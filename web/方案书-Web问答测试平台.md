# Web 问答测试平台 — 方案书（v0.1 草案）

## 1. 背景与目标

现状：客户提问需通过终端 `npx edk2-opencode --search "..."` 或 MCP 协议，门槛高。
目标：提供一个**纯浏览器**问答测试网页，客户输入问题 → 看到检索结果 + 置信度 + citation，**零终端操作**。

**核心优势（基于现有架构）**：服务端已存在 HTTP 端点 `/search`（GET/POST，返回 JSON，含 confidence 与 citation），网页只需"接"它，**无需改动 Python 检索引擎、无需改动 daemon**。

## 2. 方案选型

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **A. 静态页 + CORS（推荐）** | 纯 HTML/JS 静态页，浏览器直接 fetch 现有 `/search`；daemon 加 CORS 头 | 零后端开发、改动最小、可本地双击打开 | 需给 daemon 补一个 CORS 响应头 |
| B. Node 小服务 | 新增一个 Node HTTP 服务，转发到 daemon `/search`，顺带做限流/日志 | 同源无 CORS 问题、可加统计 | 多一个常驻进程 |
| C. 改造 daemon 自带静态页 | 在 mcp_server.py 挂一个 `/` 页面 | 单进程最简 | 混入 Python web 渲染，改动核心服务 |

**推荐 A**：改动面最小（daemon 加约 5 行 CORS 头 + 一个静态页文件），且不触碰检索核心逻辑。

## 3. 页面设计

### 3.1 布局

```
┌────────────────────────────────────────────────────────────┐
│  Edk2Agent Web 问答测试                         [连接状态] │
├────────────────────────────────────────────────────────────┤
│  [输入框: 请描述 EDK2/UEFI 问题…………]   [搜索]  [示例]      │
├────────────────────────────────────────────────────────────┤
│  回答摘要区（若接入 LLM 时显示）                             │
├──────────────────────────────┬─────────────────────────────┤
│  检索结果列表（Top N）         │  右侧信息栏                  │
│  · #1 [Title](citation) high  │  服务状态: ready ✓           │
│  · #2 ... medium              │  索引文档数: 18480           │
│  · #3 ... low                 │  数据源: wiki/docs ✓         │
│  · #4 ... poor                │  平均耗时: 820ms             │
│  · #5 ...                     │                             │
├──────────────────────────────┴─────────────────────────────┤
│  结果详情（点击展开：section 原文 + URL + 置信度标签色块）      │
└────────────────────────────────────────────────────────────┘
```

### 3.2 功能点

1. **检索面板**：输入问题 → 调 `/search?query=...&top_k=5` → 展示 Top5。
2. **置信度可视化**：结果卡片按 `high`(绿)/`medium`(蓝)/`low`(橙)/`poor`(灰) 着色，客户一眼看出"这条靠不靠谱"。
3. **citation 展示**：每张卡片显示 `Title - Section` + 可点击 URL 原文。
4. **展开详情**：点击卡片显示该 chunk 的正文片段。
5. **服务状态栏**：轮询 `/health`（ready / indexed_documents / data_sources），daemon 未启动时红点提示"请先 `npx edk2-opencode daemon start`"。
6. **示例问题**：预置 3~5 条常见 EDK2 问题（如 `PcdDebugPrintErrorLevel`、`BDS boot flow`）一键填入。
7. **可选项 — LLM 润色回答**：纯前端调用接配置的 LLM API（如 OpenAI 兼容接口），把检索结果交给 LLM 组织成自然语言回答 + citation；不配 LLM 时页面退化为"纯检索结果展示"。默认**不要求** LLM，客户可先看原始检索质量。

## 4. 技术实现要点

### 4.1 CORS（daemon 侧最小改动）

在 `mcp_server.py` 的 `/search` 与 `/health` 响应中加 CORS 头（`Access-Control-Allow-Origin: *`），约 5~8 行。若方案 B 则不需要。

### 4.2 服务地址解析

网页需知道 daemon 地址。两种方式：
- **直连模式**：网页内置可配置的 daemon URL（如 `http://127.0.0.1:58273`），从 `~/.edk2-opencode/kb/daemon.json` 读取端口；页面顶部提供"服务地址"设置框，客户可自行粘贴。
- **自动探测**：静态页先 fetch 一个固定默认端口列表，逐个测 `/health`，命中即连接（daemon 动态端口，需读 daemon.json，无法纯前端完成 → 需要用户手动填一次，或搭配方案 B）。

> 推荐：方案 A + 页面提供"服务地址"输入框（预填本地 daemon URL），同时支持 `/health` 探测失败时红点提示。若客户希望"打开即用、零配置"，升级为方案 B（Node 服务自动读 daemon.json 并反向代理）。

### 4.3 数据流

```
浏览器 HTML/JS
   │ fetch /search?query=...&top_k=5
   ▼
daemon /search 端点（现有，不动检索逻辑）
   ▼
SearchEngine（向量+FTS+RRF+重排+置信度+citation）
   ▼
JSON { results: [ {title, section, url, confidence, score, snippet...} ] }
   ▼
浏览器渲染卡片 + 状态栏
```

### 4.4 文件结构（新增，不侵入现有核心）

```
edk2-opencode-v3/
├── web/
│   ├── index.html        # 单页应用（内联 CSS/JS，零构建）
│   └── README.md         # 使用说明
└── edk2-kb/mcp_server.py # 仅加 CORS 头（约 5 行）
```

纯静态单文件（无 npm 构建、无框架依赖），可双击打开或任意静态服务器托管。

## 5. 交付与验收

| # | 验收项 |
|---|--------|
| 1 | 浏览器打开 `web/index.html`，输入问题 → 正常返回 5 条结果，卡片带置信度色块与 citation |
| 2 | `/health` 状态栏显示 ready + indexed_documents=18480 |
| 3 | daemon 未启动时页面给出明确提示，而非白屏报错 |
| 4 | 检索结果与终端 `--search` 完全一致（同一引擎同一数据） |
| 5 | 不依赖任何新 npm 依赖，不修改检索/评测核心逻辑 |
